# AI Smart Timetable System — แผนพัฒนา

ระบบจัดตารางเรียน/ตารางสอนอัจฉริยะ เป็นส่วนเสริมของ Baanmai SMS

## หลักการสำคัญ: ห้ามกระทบข้อมูลเดิม

- ใช้ตารางใหม่ใน D1 ที่ขึ้นต้นด้วย `TT_` ทั้งหมด ([schema-timetable.sql](../worker/schema-timetable.sql)) ใช้แค่ `CREATE TABLE IF NOT EXISTS` ไม่มี DROP/ALTER/DELETE กับตารางเดิม
- backend อยู่ในโมดูลแยก `worker/src/modules/tt-*.js` (action ขึ้นต้น `tt.`) ไม่แก้โมดูลเดิม
- อ่านข้อมูลเดิมแบบอ่านอย่างเดียวเท่านั้น (เช่น จำนวนนักเรียนต่อห้องจาก `STUDENTS`) ไม่เขียนกลับ
- หน้าเว็บแยก `frontend/timetable*.html` เพิ่มแค่เมนู 1 ปุ่มที่หน้าหลัก

## ข้อจำกัดทางเทคนิคที่ต้องออกแบบรองรับ

| ข้อจำกัด | ผลกระทบ | วิธีรับมือ |
|---|---|---|
| Cloudflare Worker ฟรี: CPU ~10ms/คำขอ | รัน solver บน Worker ไม่ได้ | รัน **AI Engine ในเบราว์เซอร์ (Web Worker)** แล้วส่งผลลัพธ์ไปบันทึก D1 |
| D1 ฟรี: เขียน 100,000 แถว/วัน | ห้ามเขียนทุกครั้งที่ลาก | Auto Save แบบหน่วงเวลา, บันทึกเป็นชุด (~300 คาบ/ครั้ง) |
| "AI" | LLM มีค่าใช้จ่าย และไม่แม่นเรื่องข้อจำกัดเข้มงวด | ใช้ **Constraint Solver** (heuristic + backtracking + local search) ฟรี แม่นยำ อธิบายได้ |
| สิทธิ์ 6 ระดับ | ระบบปัจจุบันมีแค่ PIN | ต้องสร้างระบบ login (ผู้ใช้ + รหัสผ่าน hash + session) ทำในเฟสท้าย |
| ผู้ปกครองดูตารางบุตรหลาน | ข้อมูลนักเรียน (PDPA) | ตารางเรียนเป็นข้อมูลรายห้อง ไม่ใช่รายบุคคล เปิดดูได้ผ่านลิงก์รายห้อง |
| นำเข้า Google Sheets | OAuth ซับซ้อน | ใช้ลิงก์ "เผยแพร่เป็น CSV" ของ Google Sheets |

## เฟสการพัฒนา (ทีละเฟส ทดสอบก่อนไปต่อ)

| เฟส | โมดูล | เนื้อหา |
|---|---|---|
| 1 ✅ | 2 + 1 | โครงข้อมูล + จัดการข้อมูลพื้นฐาน (ครู/วิชา/ห้อง/ชั้น/คาบ: เพิ่ม แก้ ลบ ค้นหา) + **เรียนควบชั้น** + Dashboard ตัวเลข/ความพร้อม/กราฟ — หน้า `timetable.html` |
| 2 ✅ | 3 + 4 | ตั้งเงื่อนไข (ครู/วิชา/ห้อง/เวลา) + AI Engine สร้างตารางอัตโนมัติ + แจ้งข้อขัดแย้งพร้อมคำแนะนำ + บันทึก/ดู/ลบฉบับตาราง |
| 3 ✅ | 5 + 6 | ตรวจสอบความถูกต้อง (แดง/เหลือง/เขียว) + แก้ตารางแบบ Drag & Drop + Undo/Redo + Auto Save + Version History |
| 4 ✅ | 8 + 10 + 11 | ส่งออก (PDF/Excel/CSV/JSON/PNG) + ค้นหาหลายเงื่อนไข + รายงาน |
| 5 ✅ | 7 + 9 | นำเข้า (xlsx/CSV/JSON/Google Sheets) พร้อมตรวจก่อนบันทึก + ข้อความวิ่งแจ้งการเปลี่ยนแปลงที่หน้าหลัก |
| 6 ✅ | 12 + พิเศษ | สิทธิ์ผู้ใช้ 6 ระดับ + มุมมองครู/นักเรียน/ผู้ปกครอง + Dark Mode + ภาษาไทย/อังกฤษ |

## เรียนควบชั้น (Combined classes)

โรงเรียนขนาดเล็กมักให้หลายชั้นเรียนรวมกัน เช่น ป.5 + ป.6 เรียนเหมือนกันทุกวิชา

- `TT_CLASS.combine_group` — ห้องที่มีค่าเดียวกัน (≥2 ห้อง) = **หน่วยการเรียน (unit)** เดียว
- จัดการผ่าน `tt.combine({class_ids})` / `tt.uncombine({class_id})` เท่านั้น (ฟอร์มทั่วไปแก้ฟิลด์นี้ไม่ได้) · กลุ่มที่เหลือ 1 ห้องถูกยกเลิกอัตโนมัติ
- **วิชาของหน่วย** = รวมวิชาของทุกชั้นในหน่วย (วิชาเดียวกันนับครั้งเดียว) → แนะนำให้สร้างวิชาเดียวที่ระบุทั้ง ป.5 และ ป.6
- **คาบที่ต้องเรียน/ช่องที่มี** คิดต่อหน่วย ไม่ใช่ต่อห้อง

กติกาที่เฟส 2–3 (AI Engine / ตรวจสอบ / Drag & Drop) ต้องยึด:
- Solver จัดตารางทีละ **หน่วย** แล้วเขียน `TT_SLOT` ให้ทุกห้องในหน่วยเหมือนกัน (วิชา/ครู/ห้อง/เวลาเดียวกัน)
- ครูหรือห้องที่ใช้กับหลายห้อง **ในหน่วยเดียวกัน** เวลาเดียวกัน = สอนครั้งเดียว **ไม่นับเป็นชน**
- ภาระงานครู/การใช้ห้อง นับแบบไม่ซ้ำ (วัน, คาบ)
- ลาก/ย้ายคาบของห้องใดห้องหนึ่งในหน่วย → ย้ายทุกห้องในหน่วยพร้อมกัน

## AI Engine (เฟส 2)

- รันในเบราว์เซอร์ผ่าน Web Worker `frontend/js/tt-solver.js` (Worker ของ Cloudflare รุ่นฟรีมี CPU ~10ms) → ผลลัพธ์ส่งไป `tt.save_version` ครั้งเดียว (แทรก `TT_SLOT` ทีละ 50 แถว)
- วิธีค้นหา: greedy เรียงคาบยากก่อน + ejection + สุ่มเริ่มใหม่หลายรอบ + local search (ย้าย/สลับคาบ) ภายใน `time_limit_sec`; จัดไม่ได้ → วิเคราะห์สาเหตุ + คำแนะนำ
- เงื่อนไขเด็ดขาด: ชั้น/ครู/ห้องไม่ชน, วันหยุด/ช่วงสอนไม่ได้/คาบแรก-สุดท้าย/คาบสูงสุด/สอนติดกันของครู, คาบต่อวัน/วันที่อนุญาต/block ไม่ข้ามพักของวิชา, ความจุห้อง
- เงื่อนไขยืดหยุ่น (`TT_CONSTRAINT.config`): กระจายวิชา, วิชาพื้นฐานช่วงเช้า, กิจกรรมช่วงบ่าย, ไม่มีคาบว่างแทรก, ภาระครูสมดุลรายวัน
- ครูผู้สอน: ใช้ครูที่ผูกกับวิชา (`TT_SUBJECT.teachers` หรือ `TT_TEACHER.subjects`) ก่อน — มีหลายคนเลือกครูประจำชั้นถ้าอยู่ในรายชื่อ ไม่งั้นเลือกคนภาระน้อยสุด ถ้าไม่มีใช้ครูประจำชั้น (`fallback_homeroom`) ถ้ายังไม่มีอีก ช่องนั้นเป็น "ยังไม่ระบุครู"
- `tt.save_version` ตรวจซ้ำฝั่งเซิร์ฟเวอร์: ปฏิเสธชั้นซ้ำช่อง และนับครู/ห้องชนข้ามหน่วยลง `stats.conflicts`

## ตรวจสอบ + แก้ไขตาราง (เฟส 3)

- ตัวตรวจ `frontend/js/tt-check.js` (`TTCheck.check`) ใช้กติกาชุดเดียวกับ solver — 🔴 error: ครู/ห้องชน, วันหยุด/ช่วงสอนไม่ได้/คาบแรก-สุดท้าย, เกินคาบสูงสุด, สอนติดกันเกิน, วิชาเกินวันละ, วิชาผิดวัน · 🟡 warning: คาบไม่ตรงหลักสูตร, ไม่ระบุครู, ครูไม่ได้ถูกกำหนดให้สอนวิชานี้, ห้องไม่ตรงประเภท, วิชาไม่อยู่ในชั้น, คาบว่างแทรก, ต่ำกว่าคาบขั้นต่ำ · ช่องอื่น = 🟢
- ตัวแก้ `frontend/js/modules/timetable-edit.js` (แท็บ "ตรวจสอบ / แก้ไขตาราง"): แก้ต่อ**หน่วยการเรียน** (ควบชั้นแก้ครั้งเดียว บันทึกทุกห้อง)
  - ลากไปช่องว่าง = ย้าย, ลากทับ = สลับ, ลากวิชาจากแถบข้าง = เพิ่ม, ลากลงถังขยะ = เอาออก; มือถือ: แตะคาบ → แตะปลายทาง
  - ขณะเลือก/ลาก ช่องปลายทาง 🟢 = วางได้, 🔴 ลาย = จะเกิดข้อผิดพลาดใหม่ (ชี้เพื่อดูสาเหตุ)
  - 🔒 ล็อกคาบห้ามย้าย · Undo/Redo 100 ขั้น (Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z) · Delete = เอาออก · Esc = ยกเลิกเลือก
  - มุมมองรายครู (อ่านอย่างเดียว แตะเพื่อไปแก้ที่ชั้น) · คลิกรายการปัญหาเพื่อกระโดดไปยังช่องนั้น
- Auto Save: หน่วง 2 วินาทีหลังแก้ล่าสุด และเมื่อออกจากแท็บ/ซ่อนหน้า → `tt.update_slots` ส่ง**เฉพาะช่องที่เปลี่ยน** (ลบ+เพิ่ม+อัปเดตสถิติใน `db.batch` เดียว atomic) — ประหยัดโควตาเขียน D1
  - `stats.rev` กันแก้ทับกันจากหลายเครื่อง (rev ไม่ตรง → `CONFLICT`); ถ้าข้อมูลบน server ตรงกับที่จะบันทึกอยู่แล้ว (คำขอก่อนหน้าสำเร็จแต่อ่านผลไม่ได้) จะรับ rev ใหม่อัตโนมัติ
  - ทุกการบันทึกลง `TT_CHANGE` พร้อมข้อความสรุป (ใช้กับข้อความวิ่งเฟส 5)
- ประวัติฉบับ: สถานะ ร่าง / จัดเสร็จ (AI) / แก้ไขแล้ว / อนุมัติแล้ว / เผยแพร่แล้ว (`tt.version_meta`, เผยแพร่ไม่ได้ถ้ายังมีครู/ห้องชน), เปลี่ยนชื่อ, ทำสำเนา (`tt.duplicate_version`) เพื่อเก็บฉบับเดิมไว้

## ค้นหา + รายงาน + ส่งออก (เฟส 4)

อ่านอย่างเดียวทั้งหมด (ไม่เขียน D1) · ข้อมูลฉบับโหลดผ่าน `window.TTData` (`timetable-report.js`) ซึ่งรอให้ตัวแก้ไขบันทึกที่ค้างก่อนเสมอ (`TTEdit.whenSaved`)

- **รายงาน** (`timetable-report.js`, แท็บ "รายงาน / ส่งออก"): ตารางเรียนรายชั้น · ตารางสอนรายครู · ตารางการใช้ห้อง · ตารางรวมทั้งโรงเรียน (รายวัน) · สรุปภาระงานสอนครู · คาบรายวิชาเทียบหลักสูตร · ผลการตรวจสอบ · ประวัติการเปลี่ยนแปลง (`tt.changes`)
  - เลือกทีละชั้น/ครู/ห้อง หรือทั้งหมด · ตัวเลือกแสดงครู/ห้อง/ช่องลงชื่อ · ค่าเริ่มต้นใช้ฉบับ เผยแพร่ > อนุมัติ > ล่าสุด
- **ส่งออก**: PDF (`js/pdf.js` jsPDF + Sarabun, 1 ชั้น/ครู ต่อหน้า, สีตามประเภทวิชา, ช่องลงชื่อ) · Excel (SheetJS, 1 ชีตต่อชั้น/ครู) · CSV (UTF-8 BOM เปิดใน Excel ได้) · PNG (html2canvas) · พิมพ์ (CSS print + `@page` ตามแนวรายงาน) · JSON (ข้อมูลฉบับเต็ม `format: baanmai-timetable` ไว้สำรอง/นำเข้าในเฟส 5)
- **ค้นหา** (`timetable-search.js`, แท็บ "ค้นหา"): คำค้นหลายคำ + ชั้น/ครู/วิชา/ห้อง/กลุ่มสาระ/ประเภทวิชา/วัน/คาบ/สถานะ (มีปัญหา, ล็อก, ไม่ระบุครู) → ส่งออก CSV/Excel · คลิกผลเพื่อเปิดช่องนั้นในตัวแก้ไข
  - **หาครูว่าง (สอนแทน)**: วัน+คาบ → ครูที่ว่าง เรียงจากภาระวันนั้นน้อยสุด / ครูที่ไม่ว่างพร้อมเหตุผล (สอน/วันหยุด/ช่วงไม่ว่าง)
  - **หาเวลาว่างร่วม (นัดประชุม)**: เลือกครูหลายคน → ตารางช่องที่ทุกคนว่าง

## นำเข้า + ข้อความวิ่ง (เฟส 5)

- **นำเข้า** (`timetable-import.js`, แท็บ "นำเข้า"): ครู · วิชา · ห้อง · ชั้น · คาบ · ตารางสอน
  - แหล่ง: .xlsx/.xls/.csv (SheetJS) · .json (ไฟล์ส่งออก `format: baanmai-timetable`) · ลิงก์ Google Sheets (แชร์ "ทุกคนที่มีลิงก์" → `/export?format=csv` หรือ "เผยแพร่ไปยังเว็บ" → `/pub?output=csv`)
  - หัวคอลัมน์ภาษาไทยตามแม่แบบ (รับชื่อเรียกอื่น/อังกฤษได้) · หาแถวหัวตารางเองใน 15 แถวแรก · แม่แบบ Excel ใส่ข้อมูลปัจจุบันให้ (นำเข้ากลับได้ทันทีโดยไม่ผิด)
  - จับคู่ข้อมูลเดิม: ครู = รหัส/ชื่อ (ตัดคำนำหน้า), วิชา/ห้อง = รหัส/ชื่อ, ชั้น = ชั้น+ห้อง, คาบ = ชื่อคาบ → ผู้ใช้เลือก "อัปเดตเฉพาะช่องที่มีค่า" หรือ "ข้าม"
  - ตรวจก่อนบันทึก: ใหม่/อัปเดต/ข้าม/ผิดพลาด (+หมายเหตุ เช่น ไม่พบครูที่อ้างถึง) · แถวผิดไม่ถูกส่ง · server `tt.import_entities` ตรวจซ้ำทั้งชุดในหน่วยความจำ แล้วเขียนใน `db.batch` เดียว (ผิดแถวเดียว = ไม่บันทึกเลย) · เพิ่ม/อัปเดตเท่านั้น
  - ตารางสอน: แบบยาว (ชั้น · วัน · คาบ · วิชา · ครู · ห้อง) หรือ JSON → ฉบับใหม่สถานะ "ร่าง" ผ่าน `tt.save_version` · คาบซ้ำ/ชั้น-คาบ-วิชาที่ไม่พบ = ผิดพลาด · ห้องในกลุ่มควบชั้นที่ไม่มีแถวของตัวเองคัดลอกตามห้องแรก · แสดงผลตรวจ `TTCheck` ก่อนบันทึก
- **ข้อความวิ่ง** (`js/tt-ticker.js` ใช้ร่วม, หน้าหลัก + แท็บ "ข้อความวิ่ง" `timetable-ticker.js`)
  - `tt.ticker` (หน้าหลักดึงใน `apiBatch` เดียวกับ settings/dashboard — ไม่เพิ่มคำขอ): ประกาศที่พิมพ์เอง (หมดอายุตามวัน) + การประกาศใช้ฉบับ "เผยแพร่แล้ว" + การแก้ไขฉบับนั้น**หลัง**เผยแพร่ (ข้อความสรุปจาก Auto Save) ย้อนหลัง `ticker_days` วัน · ฉบับร่างไม่แสดง
  - `tt.announce` · `tt.ticker_hide` (ซ่อน/แสดง) · ตั้งค่า `ticker_enabled` / `ticker_days` ใน `TT_CONSTRAINT.config`
  - วิ่งด้วย CSS (ความเร็วคงที่ 60px/s) · หยุดเมื่อชี้/แตะ · `prefers-reduced-motion` = แสดงนิ่ง · ซ่อนเมื่อไม่มีข้อความ

## ผู้ใช้ สิทธิ์ มุมมอง โหมดมืด ภาษา (เฟส 6)

- **ผู้ใช้** (`worker/src/modules/tt-auth.js`, ตาราง `TT_USER`/`TT_SESSION` — `schema-timetable-003.sql`) แยกจาก PIN/USERS/SESSIONS เดิมทั้งหมด
  - รหัสผ่าน PBKDF2-SHA256 + salt (`pbkdf2$รอบ$salt$hash`, 10,000 รอบ เพราะ Worker ฟรีจำกัด CPU — เพิ่มรอบได้ภายหลัง) · ≥ 8 ตัว · ผิด 5 ครั้งล็อก 10 นาที · ชื่อผู้ใช้ไม่มี = ใช้เวลาเท่ากัน
  - session: token สุ่ม 256 บิต · DB เก็บแค่ SHA-256 · 12 ชม. (จดจำ = 30 วัน) · เปลี่ยนรหัส/บทบาท/ปิดบัญชี = ออกจากระบบ
  - ตาราง `secret: true` ใน `db.js` → `settings.backup/restore` และ `admin.import` ข้าม (รหัสผ่าน/token ไม่หลุดผ่านไฟล์สำรอง และไม่ถูกเขียนทับจากไฟล์)
  - ผู้ดูแลคนแรก: `tt.setup_admin` ทำได้เมื่อยังไม่มีผู้ใช้เลย + ต้องใส่ **PIN ธนาคารโรงเรียน** (อ่าน `pin_bank` แบบอ่านอย่างเดียว)
- **สิทธิ์ 6 ระดับ** (`ROLES`): ผู้ดูแลระบบ (ทั้งหมด) · ผู้บริหาร (ดู · อนุมัติ/เผยแพร่ · ประกาศ) · ฝ่ายวิชาการ (ดู · แก้ข้อมูล · จัด/แก้ตาราง · ประกาศ) · ครู (ดู) · นักเรียน / ผู้ปกครอง (หน้าดูตารางเท่านั้น)
  - server: `guard()` ใน `timetable.js` ตรวจทุก action ตามตาราง `NEED` — ไม่อยู่ในตาราง = ปฏิเสธ · `version_meta` อนุมัติ/เผยแพร่ต้อง `approve` · `constraints_save` ตามคีย์ (ticker_* = announce, public_view = manage_users) · `recorded_by` = ชื่อผู้ใช้จริง
  - เผยแพร่ได้ทีละฉบับ (ฉบับเดิมที่เผยแพร่ → อนุมัติแล้ว)
  - หน้าเว็บ: `js/tt-session.js` (TTAuth) หน้าเข้าสู่ระบบ/ตั้งผู้ดูแล · ซ่อนแท็บตาม `data-cap` · ตัวแก้ไขเป็นโหมดดูอย่างเดียวถ้าไม่มี `edit_timetable` · session หมดอายุ → ขึ้นหน้าเข้าสู่ระบบ · แท็บ "ผู้ใช้" (`timetable-users.js`)
- **หน้าดูตาราง** `timetable-view.html` (`tt.public_view`): ฉบับ "เผยแพร่แล้ว" รายชั้น/รายครู · ไม่ต้องเข้าสู่ระบบ (ปิดได้ `public_view`) · บัญชีที่ผูกครู/ชั้น → "ตารางของฉัน" · ลิงก์ `?class=` / `?teacher=` · ไฮไลต์วันนี้/คาบปัจจุบัน · มือถือแสดงรายวัน · พิมพ์ · เมนูที่หน้าหลัก
- **โหมดมืด** `js/tt-theme.js` + `css/tt-dark.css` — เฉพาะหน้าระบบจัดตาราง (หน้าอื่นไม่เปลี่ยน) · จำในเครื่อง · ค่าเริ่มต้นตามระบบ · PNG/พิมพ์เป็นพื้นขาวเสมอ
- **ภาษาไทย/อังกฤษ** `js/tt-i18n.js` — พจนานุกรม + MutationObserver แปลข้อความ UI (ส่วนหัว แท็บ หัวการ์ด ปุ่ม หัวตาราง วัน สถานะ เข้าสู่ระบบ/ผู้ใช้ หน้าดูตาราง) · ข้อมูลที่กรอก (ชื่อวิชา/ครู) และข้อความรายละเอียดบางส่วนยังเป็นไทย — เพิ่มคำใน `D`/`PATTERNS` ได้

## มอบหมายการสอน (วิชา × ชั้น → ครู)

- ตาราง `TT_ASSIGN` (`schema-timetable-004.sql`, unique term+class+subject) · `tt.assign_save` (สิทธิ์ edit_data) ตรวจชั้น/วิชา/ครูมีจริง และวิชาต้องเรียนในระดับชั้นนั้น แล้วเขียนใน `db.batch` เดียว · `bootstrap` คืน `assignments`
- แท็บ "มอบหมายการสอน" (`timetable-assign.js`): แถว = วิชา (รวมตามชื่อย่อ เช่น คณิตศาสตร์ ป.1–3 + ป.4–6) · คอลัมน์ = หน่วยการเรียน (ควบชั้น = 1 คอลัมน์ บันทึกให้ทุกห้อง) · เติมทั้งแถว/ทั้งชั้น (หรือครูประจำชั้น) · สรุปภาระคาบเทียบคาบสูงสุดทันที · ไม่เลือก = "อัตโนมัติ"
- `TT.assignMap()` แปลงเป็น `unit_id|subject_id → teacher_id` (แจ้งเมื่อห้องในกลุ่มควบชั้นมอบหมายต่างกัน) ใช้ใน: solver (`input.assign` — มาก่อนครูที่สอนได้/ครูประจำชั้นเสมอ และนับภาระก่อน), ตัวแก้ไข (ครูเริ่มต้นเมื่อวางวิชา), ตัวตรวจ (`not_assigned` = คำเตือนเมื่อครูในตารางไม่ตรงกับที่มอบหมาย)

## ล็อกวิชาในคาบ (ทั้งโรงเรียน)

- เก็บใน `TT_SUBJECT.rules.fixed_slots = [{day, period_id}]` + `rules.shared` (ครูดูแลหลายชั้นพร้อมกันได้, ค่าเริ่มต้น true) — ไม่มีตารางใหม่ · server `checkRow` ตรวจรูปแบบและจำนวนไม่เกิน `periods_week`
- แท็บ "ล็อกคาบ" (`timetable-lock.js`): เลือกวิชา (รวมตามชื่อ — ทุกช่วงชั้นของวิชาชื่อเดียวกันล็อกพร้อมกัน) → คลิกช่องในตารางสัปดาห์ · กันล็อกเกินจำนวนคาบ · แจ้งวิชาล็อกช่องเดียวกันในชั้นที่ซ้อนกัน / ขัดกับ "จัดได้เฉพาะวัน" · บันทึกผ่าน `tt.import_entities` ครั้งเดียว
- solver: คาบล็อกเป็นบทเรียน `fixed` วางก่อน (`placeFixed`) และไม่ถูกย้าย/ eject/ local search · shared = ครูซ้ำได้เฉพาะระหว่างคาบล็อกด้วยกัน (นับภาระครั้งเดียว) · วางไม่ได้ → เหตุผล `fixed`
- ผลจาก AI บันทึกคาบล็อกเป็นช่อง 🔒 · ตัวตรวจ: `fixed_slot` (คำเตือนเมื่อช่องล็อกไม่ใช่วิชานั้น) และไม่นับครูชนสำหรับคาบล็อกที่ดูแลร่วม (ทั้ง `tt-check.js` และ `slotConflicts` ฝั่ง server — เผยแพร่ได้)

- **วันเรียนของแต่ละวิชา** (การ์ดในแท็บ "ล็อกคาบ / วันเรียน"): ตารางวิชา × จ–ศ ติ๊กวันที่เรียนได้ (เก็บ `rules.allowed_days`, ทุกวัน = ไม่เก็บ) — วิชาชื่อเดียวกันทุกช่วงชั้นเปลี่ยนพร้อมกัน · กันเอาติ๊กออกหมด · ⛔ เมื่อจำนวนวัน × วันละไม่เกิน < คาบ/สัปดาห์ หรือคาบที่ล็อกอยู่วันที่ไม่ได้ติ๊ก · ใช้ปุ่มบันทึกร่วมกับการล็อกคาบ

## คาบว่างร่วมของครู + สอนสูงสุดต่อวัน

- **คาบว่างร่วม** (เช่น ประชุม PLC): `TT_CONSTRAINT.config.common_free = [{ label, day, period_id, teachers:[] }]` (teachers ว่าง = ครูทุกคน) · server `cleanCommonFree` ตรวจรูปแบบ/ช่องซ้ำ (≤ 50) · การ์ดในแท็บ "เงื่อนไข" (`timetable-free.js`) เพิ่ม/ลบแล้วบันทึกทันที + เตือนเมื่อช่องเรียนของชั้นไม่พอ
  - solver: ช่องนั้นห้ามครูที่เลือก (`t_free`) และไม่นับเป็นช่องที่สอนได้ · คาบล็อกที่ทับคาบว่างร่วมยังวางตามล็อก (มีคำเตือน) · ตัวตรวจ: `t_free` = ข้อผิดพลาด
- **สอนสูงสุดต่อวัน**: `config.teacher_max_per_day` (0 = ไม่จำกัด, ตั้งในฟอร์มเงื่อนไข) หรือรายครู `TT_TEACHER.prefs.max_per_day` (ฟอร์มครู / นำเข้า "สอนสูงสุดต่อวัน") — รายครูมาก่อน
  - solver: `t_day` เมื่อครูสอนครบวันละ n · ความจุครู (`cap`) คิดวันละไม่เกิน n → เตือน `over_cap` ล่วงหน้าถ้ามอบหมายเกิน · ตัวตรวจ: `t_day` = ข้อผิดพลาด (นับช่องเวลา — ควบชั้น/ดูแลร่วม = ครั้งเดียว)

## ขึ้นปีการศึกษา/ภาคเรียนใหม่ — ดึงข้อมูลจากภาคก่อน

- ข้อมูลจัดตารางทั้งหมดผูก `term_id` (= ปีการศึกษา-ภาคเรียนใน SETTINGS) → เปลี่ยนปี/ภาค = เริ่มว่าง
- `tt.terms` (view): ทุกภาคที่มีข้อมูล + จำนวนรายการ · `tt.copy_term` (edit_data, + edit_timetable ถ้าดึงตาราง) จาก `from_term` เข้าภาคปัจจุบันเสมอ (ไม่รับ term_id ปลายทางจาก params)
  - parts: `data` (ครู/วิชา/ห้อง/ชั้น/คาบ) · `config` (เงื่อนไข + คาบว่างร่วม; ข้ามถ้าภาคนี้ตั้งแล้ว เว้นแต่ `overwrite_config`) · `assign` (ข้ามคู่ที่มีแล้ว) · `version_id` (→ ฉบับ "ร่าง" ชื่อ "จาก ปี/ภาค: ชื่อเดิม")
  - จับคู่กับของที่ภาคปัจจุบันมีแล้วด้วยคีย์ธรรมชาติ (ครู: รหัส/ชื่อไม่รวมคำนำหน้า · วิชา/ห้อง: รหัส/ชื่อ · ชั้น: ชั้น+ห้อง · คาบ: ชื่อคาบ) → ใช้ของเดิม ไม่เขียนทับ, ดึงซ้ำไม่เกิดรายการซ้ำ
  - แปลงการอ้างอิงทั้งหมดเป็นรหัสใหม่: teacher.subjects/unavailable, subject.teachers/rules.fixed_slots, room.allowed_subjects, class.homeroom/home_room/combine_group (กลุ่มใหม่), common_free, assignments, slots · เขียนใน `db.batch` เดียว · ภาคต้นทางไม่ถูกแก้
- หน้าเว็บ (`timetable-term.js`): การ์ดบนสุดของแท็บ "นำเข้า" + แถบแนะนำที่ Dashboard เมื่อภาคปัจจุบันยังไม่มีครู/วิชาแต่มีภาคอื่นที่มีข้อมูล · ค่าเริ่มต้นเลือกฉบับที่เผยแพร่ของภาคต้นทาง

## คาบว่างติดกันของครู (ต่อวัน)

- `config.teacher_min_free_block` (0 = ไม่ใช้): ทุกวันที่มีสอน ครูต้องมีช่วงว่างติดกันอย่างน้อย n คาบ — **บังคับ** (solver `t_block` ใน `fits` ผ่าน `freeShape`, ความจุครูคิดวันละ ≤ np − n) · ตัวตรวจ `t_block` = ข้อผิดพลาด
- `config.teacher_max_free_run` (0 = ไม่ใช้): ช่วงว่างรอระหว่างคาบสอนแรก–สุดท้ายของวันไม่เกิน n คาบ — **ความชอบ** (ต้นทุน ×6 ต่อคาบที่เกิน + ค่าปรับใน `evaluate` → local search ลด) เพราะบังคับระหว่างวางแบบ greedy ทำให้จัดไม่ได้ง่าย · ตัวตรวจ `t_idle` = คำเตือน · KPI แสดง "ครูว่างรอเกิน"
- นับเฉพาะคาบเรียน (ช่วงพักไม่ตัดความต่อเนื่อง) · ตั้งในฟอร์มเงื่อนไข (แท็บ "เงื่อนไข")

## โครงข้อมูล (D1)

`TT_TERM` (โรงเรียน/ปี/ภาค) · `TT_TEACHER` · `TT_SUBJECT` · `TT_ROOM` · `TT_CLASS` · `TT_PERIOD` · `TT_CONSTRAINT` · `TT_SLOT` (1 แถว = 1 คาบของ 1 ห้อง) · `TT_VERSION` (ฉบับตาราง/สถานะ) · `TT_CHANGE` (ประวัติเปลี่ยนแปลง → ข้อความวิ่ง)
