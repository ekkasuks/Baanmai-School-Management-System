# AI Smart Timetable System — แผนพัฒนา

ระบบจัดตารางเรียน/ตารางสอนอัจฉริยะ เป็นส่วนเสริมของ Baanmai SMS

## หลักการสำคัญ: ห้ามกระทบข้อมูลเดิม

- ใช้ตารางใหม่ใน D1 ที่ขึ้นต้นด้วย `TT_` ทั้งหมด ([schema-timetable.sql](../worker/schema-timetable.sql)) ใช้แค่ `CREATE TABLE IF NOT EXISTS` ไม่มี DROP/ALTER/DELETE กับตารางเดิม
- backend อยู่ในโมดูลแยก `worker/src/modules/tt-*.js` (action ขึ้นต้น `tt.`) ไม่แก้โมดูลเดิม
- อ่านข้อมูลเดิมแบบอ่านอย่างเดียวเท่านั้น (เช่น จำนวนนักเรียนต่อห้องจาก `STUDENTS`) ไม่เขียนกลับ
- หน้าเว็บแยก `frontend/timetable*.html` เพิ่มแค่เมนู 1 ปุ่มที่หน้าหลัก

## ข้อจำกัดทางเทคนิคที่ต้องออกแบบรองรับ

| ข้อจำกัด | ผลกระทบ | วิธีรับมือ |
|---|---|---|
| Cloudflare Worker ฟรี: CPU ~10ms/คำขอ | รัน solver บน Worker ไม่ได้ | รัน **AI Engine ในเบราว์เซอร์ (Web Worker)** แล้วส่งผลลัพธ์ไปบันทึก D1 |
| D1 ฟรี: เขียน 100,000 แถว/วัน | ห้ามเขียนทุกครั้งที่ลาก | Auto Save แบบหน่วงเวลา, บันทึกเป็นชุด (~300 คาบ/ครั้ง) |
| "AI" | LLM มีค่าใช้จ่าย และไม่แม่นเรื่องข้อจำกัดเข้มงวด | ใช้ **Constraint Solver** (heuristic + backtracking + local search) ฟรี แม่นยำ อธิบายได้ |
| สิทธิ์ 6 ระดับ | ระบบปัจจุบันมีแค่ PIN | ต้องสร้างระบบ login (ผู้ใช้ + รหัสผ่าน hash + session) ทำในเฟสท้าย |
| ผู้ปกครองดูตารางบุตรหลาน | ข้อมูลนักเรียน (PDPA) | ตารางเรียนเป็นข้อมูลรายห้อง ไม่ใช่รายบุคคล เปิดดูได้ผ่านลิงก์รายห้อง |
| นำเข้า Google Sheets | OAuth ซับซ้อน | ใช้ลิงก์ "เผยแพร่เป็น CSV" ของ Google Sheets |

## เฟสการพัฒนา (ทีละเฟส ทดสอบก่อนไปต่อ)

| เฟส | โมดูล | เนื้อหา |
|---|---|---|
| 1 ✅ | 2 + 1 | โครงข้อมูล + จัดการข้อมูลพื้นฐาน (ครู/วิชา/ห้อง/ชั้น/คาบ: เพิ่ม แก้ ลบ ค้นหา) + **เรียนควบชั้น** + Dashboard ตัวเลข/ความพร้อม/กราฟ — หน้า `timetable.html` |
| 2 ✅ | 3 + 4 | ตั้งเงื่อนไข (ครู/วิชา/ห้อง/เวลา) + AI Engine สร้างตารางอัตโนมัติ + แจ้งข้อขัดแย้งพร้อมคำแนะนำ + บันทึก/ดู/ลบฉบับตาราง |
| 3 | 5 + 6 | ตรวจสอบความถูกต้อง (แดง/เหลือง/เขียว) + แก้ตารางแบบ Drag & Drop + Undo/Redo + Auto Save + Version History |
| 4 | 8 + 10 + 11 | ส่งออก (PDF/Excel/CSV/JSON/PNG) + ค้นหาหลายเงื่อนไข + รายงาน |
| 5 | 7 + 9 | นำเข้า (xlsx/CSV/JSON/Google Sheets) พร้อมตรวจก่อนบันทึก + ข้อความวิ่งแจ้งการเปลี่ยนแปลงที่หน้าหลัก |
| 6 | 12 + พิเศษ | สิทธิ์ผู้ใช้ 6 ระดับ + มุมมองครู/นักเรียน/ผู้ปกครอง + Dark Mode + ภาษาไทย/อังกฤษ |

## เรียนควบชั้น (Combined classes)

โรงเรียนขนาดเล็กมักให้หลายชั้นเรียนรวมกัน เช่น ป.5 + ป.6 เรียนเหมือนกันทุกวิชา

- `TT_CLASS.combine_group` — ห้องที่มีค่าเดียวกัน (≥2 ห้อง) = **หน่วยการเรียน (unit)** เดียว
- จัดการผ่าน `tt.combine({class_ids})` / `tt.uncombine({class_id})` เท่านั้น (ฟอร์มทั่วไปแก้ฟิลด์นี้ไม่ได้) · กลุ่มที่เหลือ 1 ห้องถูกยกเลิกอัตโนมัติ
- **วิชาของหน่วย** = รวมวิชาของทุกชั้นในหน่วย (วิชาเดียวกันนับครั้งเดียว) → แนะนำให้สร้างวิชาเดียวที่ระบุทั้ง ป.5 และ ป.6
- **คาบที่ต้องเรียน/ช่องที่มี** คิดต่อหน่วย ไม่ใช่ต่อห้อง

กติกาที่เฟส 2–3 (AI Engine / ตรวจสอบ / Drag & Drop) ต้องยึด:
- Solver จัดตารางทีละ **หน่วย** แล้วเขียน `TT_SLOT` ให้ทุกห้องในหน่วยเหมือนกัน (วิชา/ครู/ห้อง/เวลาเดียวกัน)
- ครูหรือห้องที่ใช้กับหลายห้อง **ในหน่วยเดียวกัน** เวลาเดียวกัน = สอนครั้งเดียว **ไม่นับเป็นชน**
- ภาระงานครู/การใช้ห้อง นับแบบไม่ซ้ำ (วัน, คาบ)
- ลาก/ย้ายคาบของห้องใดห้องหนึ่งในหน่วย → ย้ายทุกห้องในหน่วยพร้อมกัน

## AI Engine (เฟส 2)

- รันในเบราว์เซอร์ผ่าน Web Worker `frontend/js/tt-solver.js` (Worker ของ Cloudflare รุ่นฟรีมี CPU ~10ms) → ผลลัพธ์ส่งไป `tt.save_version` ครั้งเดียว (แทรก `TT_SLOT` ทีละ 50 แถว)
- วิธีค้นหา: greedy เรียงคาบยากก่อน + ejection + สุ่มเริ่มใหม่หลายรอบ + local search (ย้าย/สลับคาบ) ภายใน `time_limit_sec`; จัดไม่ได้ → วิเคราะห์สาเหตุ + คำแนะนำ
- เงื่อนไขเด็ดขาด: ชั้น/ครู/ห้องไม่ชน, วันหยุด/ช่วงสอนไม่ได้/คาบแรก-สุดท้าย/คาบสูงสุด/สอนติดกันของครู, คาบต่อวัน/วันที่อนุญาต/block ไม่ข้ามพักของวิชา, ความจุห้อง
- เงื่อนไขยืดหยุ่น (`TT_CONSTRAINT.config`): กระจายวิชา, วิชาพื้นฐานช่วงเช้า, กิจกรรมช่วงบ่าย, ไม่มีคาบว่างแทรก, ภาระครูสมดุลรายวัน
- ครูผู้สอน: ใช้ครูที่ผูกกับวิชา (`TT_SUBJECT.teachers` หรือ `TT_TEACHER.subjects`) ก่อน — มีหลายคนเลือกครูประจำชั้นถ้าอยู่ในรายชื่อ ไม่งั้นเลือกคนภาระน้อยสุด ถ้าไม่มีใช้ครูประจำชั้น (`fallback_homeroom`) ถ้ายังไม่มีอีก ช่องนั้นเป็น "ยังไม่ระบุครู"
- `tt.save_version` ตรวจซ้ำฝั่งเซิร์ฟเวอร์: ปฏิเสธชั้นซ้ำช่อง และนับครู/ห้องชนข้ามหน่วยลง `stats.conflicts`

## โครงข้อมูล (D1)

`TT_TERM` (โรงเรียน/ปี/ภาค) · `TT_TEACHER` · `TT_SUBJECT` · `TT_ROOM` · `TT_CLASS` · `TT_PERIOD` · `TT_CONSTRAINT` · `TT_SLOT` (1 แถว = 1 คาบของ 1 ห้อง) · `TT_VERSION` (ฉบับตาราง/สถานะ) · `TT_CHANGE` (ประวัติเปลี่ยนแปลง → ข้อความวิ่ง)

ทุกตารางผูกกับ `term_id` → รองรับหลายปีการศึกษา/หลายภาคเรียน/หลายโรงเรียน
