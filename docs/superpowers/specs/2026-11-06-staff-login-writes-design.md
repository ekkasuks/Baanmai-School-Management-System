# บัญชีบุคลากรเมื่อบันทึกข้อมูล — Design

อนุมัติโดยผู้ใช้ 2026-11-06 (เลือกแบบ "บันทึกข้ามชั้นได้ แต่ต้องเข้าสู่ระบบ + บันทึกว่าใครทำ" แทนการจำกัดเฉพาะชั้น)

## หลักการ
- ดูข้อมูล: ไม่ต้องเข้าสู่ระบบ (เหมือนเดิม)
- บันทึก/แก้/ลบ: ต้องเข้าสู่ระบบด้วยบัญชีบุคลากร (TT_USER, เลือกชื่อ + รหัสผ่าน) · บันทึกข้ามชั้นได้
- ครู/ฝ่ายวิชาการ/ผู้ดูแล = บันทึกได้ทุกชั้น · ผู้บริหาร = ดูอย่างเดียว
- ผู้บันทึกมาจากบัญชีที่เข้าสู่ระบบ (หน้าเว็บพิมพ์แทนไม่ได้) · ทุกการเขียนเก็บใน WRITE_LOG
- ข้อมูลเดิมไม่เปลี่ยน — เพิ่มตาราง STAFF_HOMEROOM, WRITE_LOG (schema-staff.sql) + ค่าตั้งระบบสวิตช์บังคับ

## การตัดสินใจของผู้ใช้
- ธนาคารโรงเรียน: ใช้บัญชีแทน PIN · ครูทุกคนฝาก/ถอนได้
- หน้าตั้งค่าระบบ: ใช้บัญชีผู้ดูแลแทน PIN
- ท่องสูตรคูณ: บันทึกได้โดยไม่ต้องเข้าสู่ระบบ (คงเดิม)
- ครูประจำชั้น: เปิดชั้นของตัวเองเป็นค่าเริ่มต้นในหน้าบันทึก (ไม่จำกัดสิทธิ์)
- ข้อมูลนักเรียน: เพิ่ม/แก้/พ้นสภาพ = ครูขึ้นไป · ลบถาวร/นำเข้า DMC/สำรอง-กู้คืน/เลื่อนชั้น = ผู้ดูแล

## เฟส
1. (เสร็จ) ย้ายผู้ใช้ไป ตั้งค่าระบบ › ผู้ใช้ (`js/modules/settings-users.js`, ต้อง manage_users) · ครูประจำชั้น STAFF_HOMEROOM (`tt.staff_admin_data`, `tt.homeroom_save`, `tt.homeroom_import` จาก TT_CLASS.homeroom_teacher_id) · `auth_status.user.homeroom` · WRITE_LOG ผ่าน router (`worker/src/write-log.js` WRITE_ACTIONS) — ยังไม่บังคับ
2. (เสร็จ) `js/staff-bar.js` บนหน้าบันทึก 9 หน้า (ปุ่มเข้าสู่ระบบ/เมนูผู้ใช้, ช่องผู้บันทึก = ชื่อบัญชีแบบล็อก, เลือกชั้นครูประจำชั้นใน rec-class/p-class) · `TTAuth.signIn()` เข้าสู่ระบบแบบไม่บังคับ · auth.js ส่ง token บัญชีกับทุกคำสั่งที่ไม่ใช่ PIN · index.js ใส่ recorded_by จากบัญชี (ยกเว้น tt/geo/acad)
3. สวิตช์บังคับ (ตั้งค่าระบบ) → server ปฏิเสธการเขียนที่ไม่มีบัญชี/บัญชีผู้บริหาร · ธนาคารและตั้งค่าเปลี่ยนจาก PIN เป็นบัญชี
4. หน้า "ประวัติการบันทึก" (ผู้ดูแล/วิชาการ) กรองครู/วันที่/เมนู + CSV
